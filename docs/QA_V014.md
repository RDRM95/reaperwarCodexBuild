Validated in the managed Linux environment with Node 24.19.0 and system Chromium using SwiftShader software WebGL. GitHub CI additionally runs Node 22. Timing samples are specific to this shared cloud machine, not a prediction of local GPU FPS.

Both versions produced identical tick counts, durations, losses, winners and firing counts in every 30-second window:

These are individual timing samples, not a statistical speedup claim; occasional long ticks remain. Reaper wins are actual simulated outcomes, with no victory script. No scale beyond the tested populations is inferred from these results.

## Rendered inspection

The Pages-prefix build reached the real menu and rendered all sixteen new AU/crossover hulls. Captured their silhouettes and a mixed battle at 30/90 simulated seconds; no browser runtime, shader or WebGL errors occurred. The battle recorded 37/408 weapon firing events and 14/10 surviving ships at those samples, including fourteen macrobattery firing events by the later sample. The visual review checks original stand-in geometry and active combat; it does not claim franchise-perfect models or hardware-GPU performance.

The existing rendering benchmark now pins seed 42, supports the system Chromium override and allows bounded samples with `REAPERWAR_PERF_FRAMES` (default 30). A three-frame software-GPU check completed both views on the same paused Final Battle state at approximately 40 seconds, with 178 surviving hulls:

| View | LOD off draw calls | LOD on draw calls |
| --- | --- | --- |
| Tactical | 1,623 | 615 |
| Follow | 1,309 | 695 |

This verifies rendering workload reduction, not an FPS guarantee. Short GPU submission samples and SwiftShader timing vary considerably; measure end-to-end frame pacing on actual local hardware before drawing conclusions about real-time performance. The prior full 30-frame helper also completed both views; its unpinned briefing seed made it unsuitable for exact replay, which is why the helper now fixes the seed.

## Reproduce

```bash
npm ci
npm test
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
node --import tsx/esm scripts/combat-benchmark.ts
VITE_BASE=/reaperwarCodexBuild/ npm run build
VITE_BASE=/reaperwarCodexBuild/ npm run preview -- --host 127.0.0.1 --port 4173
# Against that running prefix build:
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node --import tsx/esm scripts/model-review.mjs e2e-screenshots/au http://127.0.0.1:4173/reaperwarCodexBuild/ au
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run perf -- http://127.0.0.1:4173/reaperwarCodexBuild
```

Omit `CHROMIUM_EXECUTABLE_PATH` when using Playwright's installed browser. Stop other CPU-heavy workloads before timing. Model screenshots and generated reports are intentionally ignored. See [known limitations](../KNOWN_ISSUES.md) and the [deferred Extreme Scale brief](EXTREME_SCALE_BRIEF.md) for unsupported capabilities; this release does not implement or benchmark the requested 75,100-vessel engine.
